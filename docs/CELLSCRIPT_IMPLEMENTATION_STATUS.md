## Backend Phase C/D Status

Phase C has started but is not finished. The internal ELF backend now has an explicit `MachineLayoutPlan` boundary that parses assembly, assigns section layout, computes text/rodata sizes, records branch-relaxation decisions, owns an explicit `MachineBlock` / `MachineTerminator` view over the text section, owns the derived `MachineCfg` edges for fallthrough, jump, conditional branch flow, and local call targets, validates that machine blocks cover every executable text op exactly once, owns a validated `MachineLayoutOrder` permutation over CFG blocks with planned `MachinePlacedBlock` byte offsets, rejects branch targets that do not start text blocks, and reports backend layout metrics before final ELF emission. This is the first layout-aware machine-block/CFG layer; it is not yet a full machine-level optimizer with block reordering, tail merging, cold-block sinking, or structured optimization passes.

Phase D is active. Bundled examples are now gated by ELF size budgets, assembly-shape budgets for line count, shared fail handlers, shared epilogues, required helper uniqueness, and backend-shape budgets from `analyze_backend_shape` for text size, relaxed branch count, maximum conditional-branch displacement, machine block count, maximum machine-block byte size, call edge count, unreachable machine-block count, CFG edge count, block coverage, and layout-order coverage. `BackendShapeMetrics` is serializable, and the examples test suite emits a JSON backend-shape report when `CELLSCRIPT_BACKEND_SHAPE_REPORT=/path/to/report.json` is set. The release gate now sets this variable by default to `target/cellscript-backend-shape/backend-shape-report-<mode>.json`, so CI/release runs produce an archiveable shape artifact in addition to enforcing tightened per-example budgets. The release gate also asserts that the backend layout plan, machine-block and CFG structures, public backend-shape analyzer, serializable report path, layout metrics test, explicit machine-block test, invalid CFG target test, and bundled shape-budget test remain present. The latest quick gate run on 2026-04-21 passed `cargo fmt`, `cargo check`, all CellScript library/CLI/example tests, Spora adaptor tests/examples, wallet CellScript and CKB TYPE_ID focused tests, CKB compile-only acceptance, and `git diff --check`.

## V1 Core-language convergence

The v1 executable core is defined as the Cell lifecycle language boundary: `resource`, `shared`, `receipt`, `consume`, `create`, `transfer`, `destroy`, `claim`, `settle`, `action`, `fn`, and `lock`.

The close target is not "all generalized protocol semantics are executable". The close target is:

- supported paths are executable or classified as `checked-runtime`
- incomplete paths are explicit `runtime-required` obligations with stable blocker classes, or fail closed
- post-v1 features are not represented as v1 promises
- CLI JSON and `--deny-runtime-obligations` expose the remaining blocker classes used by release policy

The current blocker-class coverage for v1 convergence is:

| Blocker class | Surface | CLI release-gate visibility |
|---|---|---|
| `transfer-output-relation-gap` | unsupported transfer output relation/conservation shapes | Covered |
| `resource-conservation-proof-gap` | generalized resource conservation beyond the restricted checked subsets | Covered |
| `claim-source-predicate-gap` | signer-backed claim source predicates not fully verifier-covered | Covered |
| `finalization-policy-gap` | non-lifecycle/generalized settle finalization policy | Covered |
| `linear-collection-ownership-gap` | action-visible `Vec<CellType>` ownership model | Covered |

Excluded from v1 core convergence: first-class `launch`, first-class `pool`, user-defined generics, registry distribution, schema migration, and executable Wasm.

Or, more bluntly:

> **Core compiler path is real. Complete stateful contract semantics are still incomplete.**

The trustworthy path today is:

1. Resolve input from `.cell`, package directory, or `Cell.toml`
2. `lex -> parse -> type check -> minimal IR lowering -> codegen`
3. Emit `riscv64-asm` or `riscv64-elf`
4. Write artifact to disk via `cellc`

## V1 close interpretation

For the current repository definition, no remaining item is required to close
the **v1 core-language convergence gate**. That gate is already closed because
the supported executable core has stable checked/runtime/fail-closed
classifications and the known residual gaps are release-policy-visible through
blocker classes.

That does not mean the whole design proposal, protocol surface, or external
release package is complete. To keep v1 closed, the release boundary must keep
these surfaces explicitly outside the v1 core promise unless the gate is
reopened: first-class `launch`, first-class `pool`, user-defined generics,
registry distribution, schema migration, executable Wasm, and complete AMM
economics.

Before a release tag or external compatibility commitment, the remaining
release/product-readiness work is:

- rerun the full release gate on the final worktree, including `cargo test -p cellscript`, the scheduler/trusted-summary integration tests, and `git diff --check`
- either close or explicitly defer generalized resource conservation beyond the restricted checked subsets
- keep unsupported transfer/claim/settle/finalization relations policy-visible through blocker classes until executable
- keep AMM/Pool economic invariants and first-class Pool admission as protocol-pattern debt, not v1 language-core semantics
- keep external RPC trusted-summary submission out of scope unless an authenticated trust policy is added
- document SDK/developer-tooling limits separately from compiler-core closure

## Semantic completeness

The compiler is no longer just “shape-complete”. Some real semantics are now enforced end-to-end:

- function parameters get IR bindings
- parameters are spilled to stack slots in codegen
- local bindings participate in computation
- `return <expr>` now lowers into actual return-value generation
- no-return `fn` calls lower as destinationless IR calls; their internal `Unit` result cannot be bound to locals or returned from value-returning entrypoints
- `assert_invariant` lowers to a fail-closed branch and has internal `Unit` type, so it cannot be bound as a value or used as a tail return expression; assertion messages must be static string literals rather than runtime expressions
